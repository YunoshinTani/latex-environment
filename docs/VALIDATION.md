## フォルダ分けとヘルパー

以下を確認しました。

- 5種類の使用例を `00-使用例/` 内に置き、各ルート文書の隣の `.latexmkrc` でビルドできること。
- 親のVS Code設定が出力先を `%DIR%/export` とし、実験ごとに出力が分かれること。
- 学校形式を別フォルダにコピーし、ルート文書を `測定結果.tex` に変更してもビルドできること。
- PowerShellヘルパーをリポジトリ外から、使用例名・任意フォルダ・明示したTeXファイル名で呼び出せること。
- PowerShellヘルパーが呼び出し元の環境変数を復元すること。
- 通常清掃 `-c` でPDFとSyncTeXが残り、その後に再ビルドできること。
- PowerShell 7での実行と、Windows PowerShell 5.1の構文解析。
  5.1での実行はこのPCの実行ポリシーにより未確認です。
- POSIXシェルヘルパーの構文。
- VS Code設定のJSON構文と、使用例一覧JSONの全5件の参照先。
- GitHub ActionsのYAML構文、8種類のビルド定義、各ルートファイルの存在。
- 公開対象に元環境の個人名・接続先・PC固有パスを含めないこと。

実際の学校レポートは変更していません。
公開用の学校形式は架空の情報で新規作成し、学校配布の `r08ec-exp.sty` は同梱していません。

## Windowsの日本語パスについて

このPCでは `00-使用例`、`実験報告書.tex`、`測定結果.tex` などの日本語名でビルドできました。
一方、`03-図表と参考文献` というフォルダ名では、Windows版PerlがCP932の
「表」に含まれるバイトをパス区切りと誤認する現象を確認しました。
そのため使用例は `03-数式とグラフ` としています。
すべての日本語名が安全という保証はできません。別のPCにも配布する実レポートでは、
`01-light-sensor` のような半角英数字とハイフンのフォルダ名がより確実です。

WindowsではTeX Live内蔵Perlを使うようにしています。
このPCのMSYS2側のPerlではBibTeXへのパスが不適切になるため、外部Perlを自動選択させません。

数式とグラフの日本語クラスは、pLaTeXとupLaTeXが同じupTeXバイナリーを使う場合にも、
jsclassesの内部文字コード判定で適切に選択する構成です。
補助ファイルの格納先はlatexmkの出力先に従い、別の出力先を指定した検証でも衝突しないようにしています。
